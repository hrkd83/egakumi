# CMの認証案内

個人接続の再認証が必要なときにBrokerへ開始を依頼し、検査済みの短命URL・仮セッション・完了確認情報を呼出アプリへ返すsnippetです。既存のconnection・session-use・outboundへ生成時にinline展開し、新しいAzureフラグメントやinclude-fragmentの入れ子は追加しません。

同名C#はBroker応答検査・429の再試行秒・公開応答本文の固定3区画を所有します。XMLは開始条件、主体・秘密の送信、短い状態の引継ぎ、監査、ヘッダーと停止順を所有します。親XMLの挿入markerは従来どおり`__CREDENTIAL_CHALLENGE_XML__`です。

## MOD-95の変更

外部応答の有無とHTTP状態を先に確認し、非200では本文を読みません。challengeは403を403、429を429、その他の非200と応答なしを503へ分類します。200だけ本文を必須とし、従来の本文サイズ・need_login・秘密の形式・protocolVersion・仮セッション・期限・公開origin内のURL・返却項目の条件を維持します。

同時にconnection側も、Broker authorizeは403を403・409を409、Graph本人確認は401を409・403を403へ分類してから、200だけ本文を検査する順序へ揃えます。両方ともその他の非200と応答なしは503です。本文のない拒否が一時障害へ置き換わることを防ぎ、本文がある拒否にも同じ分類を使います。接続所有者・本人・provider・tenant・期限・失効・SQLの使用直前確認は変更しません。

BicepとPython rendererは、この同名XML/C#から応答検査を展開して設定値・監査を差し込みます。配備と保護された読戻し期待sourceは同じ展開済みchallengeを使います。正本はこのディレクトリで、旧ルートの`credential-challenge.xml`は撤去します。
