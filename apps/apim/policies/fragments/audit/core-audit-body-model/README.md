MOD-124の関連28件は43.335秒で全件成功しました。準備済み制約を使うこと、Liveの固定モデルは本文読取り0、本文モデルの保持、対象外と内部解析失敗の既存空文字、全protocol生成・配備／保護source一致・容量・Razor・所有を確認しました。通常HTTPだけの呼出しを維持し、共通の監査モデル選択など他部品の設定取得は変更しません。Azure反映・実HTTP監査受入は未実施です。

AzureのPolicy fragment名`core-audit-body-model`を維持し、同名XML／C#を正本として管理します。XMLは呼出し・固定PolicyIdと説明、C#は`gatewayAuditBodyModel`を返す式を担当します。初回の配置整理と、後続の取得元・内部失敗分類の変更を下記で区別します。

通常HTTPのモデルAPIで、入力検査とモデルaliasの書換えを通過した後に呼び出します。Live作成では選択済み操作の固定モデル名を使い、`bodyModel`・`textEmbeddings`・`rerank`・`statelessResponses`では本文の`model`を読みます。他の操作は空文字を返し、本文を読みません。本文を読む式を含むため、WebSocket・MCPの中継へ共用しません。

本文の読取りは`preserveContent:true`で行い、後続へ同じ本文を渡します。モデル一覧とは照合せず、既存の文字種・長さを満たす未登録モデルも監査へ渡します。本文全体・入力文・資格情報を変数やログへ保存する処理は加えません。

MOD-124で、先行するHTTP操作設定が選択・準備した`gatewayOperationConstraint`を直接解析する方式へ揃えました。`gatewayControlSettings`の再解析と操作IDの選択・操作一覧の検索を省き、モデル名の文字種・長さ確認と読取り失敗時の空文字を維持します。内部設定不備と本文読取り不備の分類は別の棚卸項目です。

BicepとPythonの生成処理、試験の参照先を同じ正本へ切り替え、旧`audit-body-model.xml`を撤去しました。Bicepの配備値と保護された読戻しsourceは、同じ生成済みXMLを使います。C#はこのXMLだけが直接所有し、Pythonも説明をXMLへ展開します。
