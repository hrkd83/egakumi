# MCPの予約メタデータパス

生成MCPと外部MCPのAPIポリシーへ、共通Inboundの`base`より前に差し込むXMLです。AzureのPolicy fragmentには登録しません。短い条件式はXML内に置き、空のC#ファイルを作りません。

`/.well-known/oauth-protected-resource`で終わるパスと、その直後に`/`が続く子パスを404で終了します。APIのprefix・任意の深さ・大小文字の扱いは維持します。`oauth-protected-resource-example`などの別名は、この条件だけで拒否しません。似た別名の後ろに本物の予約パスがあっても検出します。

目的は、MCP下流やAPIMの個別メタデータを意図せず公開・転送しないことです。共通のメタデータを200で返す入口を、この部品が提供するわけではありません。API定義の予約prefix検査とは、検査する入力と時点が異なります。

認証・要求監査の準備前に、本文なし404とAPIMの要求IDで終了する既存契約を維持します。Bicep生成と公開時の固定構造検査は、同じXMLを正本として使います。APIMのURL正規化・実routingは、まとめ反映時の受入で確認します。
