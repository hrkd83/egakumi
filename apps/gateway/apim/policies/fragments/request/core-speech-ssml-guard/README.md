# Speech TTSの本文サイズと宣言の確認

音声合成で使うSSML本文を一度だけ読み出し、本文サイズとDTD／ENTITY宣言を確認する部品です。サイズ検査のための読取りとSSML検査のための読取りを、この部品へまとめます。元の本文は保持し、Speechへ送る本文を書き換えません。

Azureのフラグメント名・フォルダ名・XML・C#の名前は、すべて`core-speech-ssml-guard`に揃えます。

| 資材 | 役割 |
| --- | --- |
| `core-speech-ssml-guard.xml` | 同名C#の式を実行し、結果変数を設定する外枠 |
| `core-speech-ssml-guard.cs` | 本文サイズと宣言を確認する本体。生成時に同名XMLへ説明コメントとともに展開する |

ほかのフラグメントを内部から呼ばず、監査やHTTP応答もこの部品では行いません。呼び出し元のHTTP APIテンプレートが結果を読んで処理します。

## 呼び出す順序

1. APIが共通のキー／Bearer認証、操作設定の選択、認証済み利用者情報の引き渡しを実行する。
2. `core-model-limits`が、選択済みの本文形式とサイズ上限を確認する。TTSは`requestBodySizeCheck: declared`なので、申告サイズの上限超過による早期413を残し、この共有部品では本文を読み出さない。
3. HTTP APIテンプレートが、生成済みの`speechSsmlOperationIds`に現在の操作IDが含まれる場合だけ、`core-speech-ssml-guard`を呼ぶ。
4. この部品が本文を一度だけ読み、実サイズを確認してからSSMLの宣言を検査する。
5. 拒否の結果ならAPIが監査を記録し、400または413を返す。通過した要求だけが利用枠処理、下流の認証準備、`accepted`監査、転送へ進む。

以前のOperationポリシーの`<base />`後から、APIの共有サイズ検査直後へ移します。実サイズ超過を、利用枠処理や`accepted`監査より前で停止できる順序を維持します。

## 入力と出力

| 変数・情報 | 内容 |
| --- | --- |
| `gatewayControlSettings.speechSsmlOperationIds` | 配備時に生成する対象操作IDの配列。呼び出し元が対象の選択に使う |
| `gatewayOperationConstraint` | 先行処理で選択済みの操作設定JSON。`maxRequestBytes`は直前の共有部品で検証済み |
| 要求本文 | `preserveContent: true`でバイト配列へ読み、元の本文を保持する |
| `gatewaySpeechSsmlDecision` | `allowed`・`status`・`code`を持つ結果のJSON文字列 |

| 結果 | `allowed` | `status` | `code` |
| --- | --- | --- | --- |
| 検査を通過 | `true` | 200 | `SPEECH_MARKUP_ALLOWED` |
| 実本文が選択済み上限を超える | `false` | 413 | `REQUEST_TOO_LARGE` |
| DTD／ENTITY宣言など既存の拒否条件に一致 | `false` | 400 | `INVALID_SPEECH_MARKUP` |

サイズ上限は選択済みの`maxRequestBytes`を直接参照し、同じ設定検査を重ねません。内部JSONの読取りなどが例外になった場合は、APIの既存`on-error`へ進み、基盤側の500として扱います。この部品専用の設定エラーコードは追加しません。

API側の拒否分岐が、結果の理由・応答コードを監査へ渡し、要求IDを返します。SSML拒否の公開エラーコード`InvalidSpeechMarkup`は維持し、本文や宣言の内容を監査へ記録しません。

## 本文サイズとSSMLの検査

実本文が上限を超える場合は、文字列化する前に413の結果を返します。標準TTSの上限は524,288,000 bytesであり、その値ちょうどはサイズ検査を通過します。Content-Lengthが省略されたり比較できなかったりしても、この部品では実本文の長さを確認します。

サイズ検査後は既存の走査を使います。UTF-8／16／32を判別して文字列へ変換し、小文字化してDTD／ENTITY宣言を探します。UTF-8へ再エンコードする処理ではありません。XMLパーサーや外部エンティティの解決は呼びません。

エスケープされた例文、コメント、CDATA、処理命令内の文字列は宣言として拒否せず、通常タグの引用符も考慮します。既存の未対応エンコーディング等の拒否条件は維持します。SSML全体のスキーマ検証や音声・時間など提供元の条件はSpeech側が判断します。

## 対象と棚卸の状態

対象は、従来の`requiresSpeechSsmlGuard`が選んだ標準TTS操作です。API・操作・POST・`/synthesize`・本文形式`text`・既存のSSML設定による対象範囲を維持し、配備時に操作IDの表へ変換します。ほかのXML入力や音声認識へ検査を自動追加しません。C#本体にはAPI名や操作名による対象選択を持たせません。

標準の`declared`指定は、Speech STT・音声ファイルの文字起こし・画像編集にTTSを加えた4操作です。前の3操作は共有部品による全量読取りを省き、TTSはこの専用部品で実サイズを確認します。DocumentやJSONの未棚卸処理は変更しません。

本文のバイト配列読取りは一度になりますが、SSML走査のための全文の文字列化・小文字化は残ります。AppGWやAPIMの受信・保持処理、完全な無バッファ転送を確認した変更ではありません。

本構成のローカル資材の改修と、承認済みソースのAzure反映・読戻しは完了しました。TTSはキー／Bearerの正常WAV応答とDTD宣言拒否の400、それぞれに対応する認証済み利用者情報・応答・拒否理由とAppGW監査の相関を、実接続の限定受入で確認済みです。大本文413やその他の音声条件は未検証であり、この部品の受入全体は未完了です。従来のSSML拒否試験の結果を、新しい呼出順とサイズ検査の実環境確認へ読み替えません。
