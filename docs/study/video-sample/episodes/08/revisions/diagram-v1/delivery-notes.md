# 第8回 再生・保存の確認

2026-11-02（JST）。第5・6回の回専用サーバーを参照し、第8回の[serve.py](serve.py)を用意した。共有プログラム、既存のサーバー、他回の成果物は変更していない。

## 再生サーバー

リポジトリルートから次を実行する。完成した`index.html`と`egakumi-study-08.mp4`が必要。

```sh
python3 -u docs/study/video-sample/episodes/08/serve.py
```

`127.0.0.1`の空きポートをOSに選択させ、表示されたURLで`output/lesson-08-gemini/`だけを配信する。シンボリックリンクで出力先の外へ出るパスも拒否する。Byte Rangeに対応し、ブラウザーからの途中再生・チャプター移動に必要な`206`、`Content-Range`、`Accept-Ranges`を返す。成果物の正本はMP4ファイルで、localhostのURLはこのプロセスが動いている間の閲覧用。

## 実施した検査

構文検査と、ソケットを開かないインメモリーのHTTPハンドラー検査を実施し、以下が合格した。検査対象の内容には第8回の`serve.py`自身を使い、サーバーの起動や出力ファイルの作成は行っていない。

- 通常GET：`200`と元ファイルに一致する全バイト。
- 範囲GET：`bytes=0-7`、末尾範囲、終端省略に対する`206`と対応するバイト。
- 範囲HEAD：`206`と本文なし。
- 範囲外、逆転した範囲、ゼロ長末尾範囲、複数範囲：`416`と本文なし。

## 完成MP4で確認する項目

完成後に上記サーバーを起動して、表示されたポートで次を確認する。

1. `/`のHTMLが取得でき、第8回の題名・動画・チャプター・保存リンクが表示される。
2. `/egakumi-study-08.mp4`へのHEADで`200`、`Content-Type: video/mp4`、ファイル実サイズと一致する`Content-Length`を確認する。
3. 同MP4への`Range: bytes=0-1023`で`206`、1024バイト、実サイズ入りの`Content-Range`を確認する。
4. ブラウザーで動画メタデータと再生尺を確認し、先頭・中盤・終盤への移動ができることを確かめる。
5. 動画・字幕・台本の保存リンクが同じ第8回の成果物を指すことを確認する。
6. プレビューと完成動画から、冒頭の3人の顔・名前・役割、代表図と字幕、最後のロゴを目で確認する。

## 完成後のHTTP確認

稼働中の[第8回ローカル再生ページ](http://127.0.0.1:52168/)に読み取り専用で接続し、以下を確認した。既存サーバーの停止・再起動・プロセス変更は行っていない。詳細は[delivery-check.json](delivery-check.json)。

- HTMLのGETは`200`。ローカルの`index.html`と全バイト一致し、題名は`第8回｜基盤管理者の接続と作業実行`。
- 動画の`src`、日本語VTT、台本、動画保存・字幕保存・共通クロージング保存のリンクが第8回の成果物を指すことを確認。動画保存リンクには`download`属性がある。
- VTTと台本のGETは`200`で、担当回のローカルファイルと全バイト一致。VTTの`WEBVTT`ヘッダー、台本の第8回表題も確認。
- MP4のHEADは`200`、`Content-type: video/mp4`、`Accept-Ranges: bytes`、`Content-Length: 47916376`。ファイル実サイズと一致し、HEAD本文は0バイト。
- `Range: bytes=0-1023`は`206`、本文1024バイト、`Content-Range: bytes 0-1023/47916376`。ローカルMP4の先頭1024バイトと一致。
- `Range: bytes=-1024`は`206`、本文1024バイト、`Content-Range: bytes 47915352-47916375/47916376`。ローカルMP4の末尾1024バイトと一致。
- 範囲外の`Range: bytes=47916376-`は`416`、`Content-Range: bytes */47916376`、本文0バイト。
- MP4のSHA-256は`6cbfb3874a7e4028a4df73c83dc848ef83c3ea18beeda5b670bdab5dba9c3c3e`で、制作担当から渡された完成値と一致。

この補助作業では、ブラウザーの実再生・完成MP4の映像目視・聴感は確認していない。担当セッションの最終検証と区別し、その結果は`production.md`へ記録する。

## 既存ASRの確認

Pythonの`whisper`、`mlx_whisper`、`faster_whisper`、`vosk`、`speech_recognition`、`transformers`、`torch`、`mlx`は未導入。`/opt/homebrew/bin/whisper-cli`は導入済みでヘルプ表示まで確認したが、通常のWhisperキャッシュ、Homebrewのshare/Cellar、ユーザーの`.cache`・`.local/share`・Downloads、workspaceのモデルファイル名検索ではローカルモデルを見つけられなかった。新規インストール・モデルダウンロード・認証情報の参照は行っていない。この確認だけで音声内容の認識が利用可能とは扱わない。
