# Tool Gatewayの受入試験

[動作テストの共通手順](integration-tests.md)で用意した検証用利用者と合成入力を使います。採用する下流接続方式ごとに実行し、入口認証の結果と下流へ接続した本人を確認します。

| 対象 | 合格条件 |
| --- | --- |
| Graph /me（Bearer） | `Gateway.Invoke` を持つ利用者本人のプロフィールをOBOで取得する。無効なトークン、権限不足、OBO証明書不整合は失敗として記録する |
| Graph /me（例外キー） | 購読の範囲内で本人確認、CMへの同意、接続状態確認、本人のGraph実行が成功する。別購読・別本人・期限切れセッションでは利用できない |
| CMとBrokerの照合 | 接続解除後の失効、使用中と回収対象の区別、再認証、定期照合の実行結果と残存件数を確認する |
| PII REST | 合成PIIを含む正規リクエストで、種別とマスキング済み結果を確認する。未認証や公開契約外の要求の結果を区別する |
| PII MCP | 対応transportで初期化、ツール一覧、ツール呼び出しを行う。本文・結果が採用する監査の対象になることを確認する |
| 採用する外部REST／MCP | 登録済みの操作、固定バックエンド、下流資格情報、タイムアウト、利用者・購読の範囲を確認する |

[本人接続の契約](../reference/identity/credential-manager-login.md) · [Credential Brokerの運用](../operations/credential-broker.md)

## 文書解析の受入

| 条件 | 合格条件 |
| --- | --- |
| 入力とジョブ | 原本・`base64Source`・`urlSource`の採用方式を個別に確認する。開始の202と、同じ所有者が発行された参照で取得する完了結果を照合する |
| 運用上の境界 | 大容量と提供元上限、指定したオプションの転送、認識しない入力の提供元応答、待機とバックエンド失敗を区別する |
| 所有者・有効期限 | 別ユーザー・別購読・期限切れ・別ジョブの参照が拒否される。正規の取得経路は本文なしGETを使う |
| WAFと監査 | 入力文書URLの除外が承認した操作・項目・規則だけに適用され、監査で原本の形式・サイズなどの参照情報を照合できる |
