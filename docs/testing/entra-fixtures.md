# Entraテストデータの準備例

[動作テスト仕様](../../INTEGRATION_TESTS.md)を実施する環境で、以下の合成データを用意するための例です。実際の組織の準備記録・UPN・Object ID・所属・資格情報は配布していません。例示名は自身の規則へ置き換え、対象テナントを確認してから準備します。

| 参照名 | 用意する状態 |
| --- | --- |
| U-A / U-B | 異なる検証ユーザー。ともにG-Aへ所属し、U-BだけG-Bにも所属する。 |
| U-C / U-X | U-Cは適格グループ非所属、U-Xは使用権限のある別テナントの検証アカウント。 |
| G-A / G-B | 採用したグループ名規則に一致する所有候補。例: `EXAMPLE_TEST_A` / `EXAMPLE_TEST_B`。 |
| G-N | グループ名規則に一致しない対照。例: `OUTSIDE_TEST`。 |
| G-H | 名前変更・対象外化・廃止を検証する専用グループ。通常の組織グループを使用しない。 |
| G-ADMIN | 検証用の基盤管理グループ。実環境の既存管理者の権限を試験都合で変更しない。 |

ユーザー属性の会社・部署・役職・所在地・従業員ID・連絡先には架空の値を用い、未設定の表示も確認します。必要のないライセンス、メールボックス、ディレクトリロールを追加しません。

資格情報はユーザーごとに異なる乱数とし、利用先の規則に従って保護します。初期パスワード・変更後パスワード・回復情報をGitや公開記録へ書きません。実UPN・Object ID・所属の対応記録はGit管理外の保護領域に保存します。

会社C-A/C-B、購読K-A/K-B/K-L/K-D、本人接続は該当テストの手順で作成します。準備が済んだだけで試験合格とは記録しません。使用した検証データの保持・回収方針を試行開始前に決め、通常利用者の接続や他組織のデータを変更しません。
