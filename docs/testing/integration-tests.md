# 構築後の動作テスト仕様書

実施時の環境・revision・入力・期待結果を確認し、新しい試行として記録します。

構築資材の試験は [構築テスト仕様書](construction-tests.md)、開発手順は [DEVELOPMENT.md](../../DEVELOPMENT.md)、導入順は [README.md](../../README.md) を参照してください。

## 1. 対象と仕様の基準

- 実施時には、この公開コードのrevisionと対象環境の設定を固定します。過去の非公開実行結果を合格の根拠に使いません。
- 対象: 構築済み環境の経路・証明書・監視、APIM認可、CM本人接続、Azure SQL、Entraグループに基づくAPIキー管理、Model Gateway、Tool Gateway、監査・運用。
- 正式な提供元: [API定義](../../apps/gateway/apim/apis/)、[構築入力](../../params/)、[モデル・API設定](../../config/)、[Gateway資材](../../apps/gateway/)、[Portal](../../apps/portal/)。構築用のexample設定を実環境の設定値と取り違えません。
- 画面の準備中機能: Hosted Agent APIとA2A。準備中表示・誤操作防止を試験し、未実装の実行成功を受入条件にしません。
- WAFは[データ欄の個別除外](../../apps/gateway/waf-data-exclusions.json)、[raw本文の限定調整と補完保護](../../apps/gateway/waf-raw-body-controls.json)、[SSML宣言ガード](../../apps/gateway/apim/policies/speech-ssml-guard.xml)を仕様基準とします。正規データの通過と制御欄・隣接経路の遮断を別々に確認し、匿名401をAPI機能成功と数えません。
- API数・モデル数の一致だけでは合格としません。実施時の設定からAPI、operation、モデル、リクエストプロファイル、接続方式を列挙し、該当行を対象ごとに展開します。

## 2. 実施方法と記録

### 2.1 実行記録

実施前の仕様と以下の実行記録は、`.local/<environment>/evidence/<run-id>/`へ保護保存します。[共通ルール](../../AGENTS.md)に従い、実params・秘密・state・証跡を同じ環境の領域内で分け、`.azure/`はazd専用とします。本書の結果欄には、依頼者の指定により、今回までの判定と確認範囲・残件を環境非依存の要約として記録します。実値・試行の識別子・原本証跡の参照先・実設定から導出したhashは公開版へ持ち込みません。

| 項目 | 記入欄 |
| --- | --- |
| 試行ID・担当者・開始終了日時 | 実施時に記入 |
| コードrevision・対象環境・配備revision・イメージdigest | 実施時に非公開記録へ記入 |
| params参照・秘密を除いた設定hash | 実施時に非公開記録へ記入 |
| Gateway・Portal origin・認証tenant・SQL参照名 | 自身の環境を非公開記録に対応付ける。例: `gateway.example.com` / `portal.example.com` |
| API・operation・モデル・接続方式の対象一覧 | 実施時に記入 |
| 製品・購読・所有グループ・検証ユーザーの参照名 | 実施時に非公開記録へ記入 |
| ブラウザー・OS・接続経路・プロキシ条件 | 実施時に記入 |
| 採用する構成・除外項目・理由 | 実施時に記入 |
| 前提試験・想定外作業の承認条件・破壊的試験・切戻し条件 | 実施前に非公開記録へ記入 |

会社・利用者名等が表示される画面の原本は、識別子のマスクや画像加工を加えずに保護保存します。実環境の原本や固有情報を公開文書・配布物へ持ち込みません。公開用の説明には実値を流用しない独立した架空の例を用い、フィールド名やAPI経路等の再現条件を保ちます。

検証用の合成ユーザー・グループは、[Entraテストデータの準備例](entra-fixtures.md)に従って自身の環境へ準備します。事前準備と試験合格は区別し、実際に確認した結果だけを記録します。

### 2.3 展開・判定のルール

1. 行のIDに必要に応じて枝番を付ける。例: `TXT-01/<deployment>/responses/stream`、`RT-01/<model>/ws`。モデル別・方式別の実測結果を1行にまとめない。
2. 正常系はGateway直呼びとPortal経由を区別する。Portalが公開していない画像編集等を「Portalで実行できない」という理由で不合格にしない。
3. 各行の「前提・入力・手順」を実行し、HTTP状態・公開エラーコード・応答構造・SQLの状態・UIの状態を必要な範囲で照合する。自然言語・画像・音声の内容は完全一致を求めず、目的に合う実出力を人が確認する。
4. 状態変更を伴う項目は専用データを使う。削除、同期、証明書障害、権限変更、ネットワーク遮断等は隔離環境または明示した実施範囲で行い、復元と残存確認までを同じ試験とする。
5. 月・日単位の待ち時間は、標準値の設定確認と、許可範囲内の短縮設定による境界試験に分ける。短縮試験だけで実際に7日・30日経過したと記録しない。
6. 課金するAPIは最小限の試行とする。最大出力値の初期表示はUI・要求で確認し、毎回最大長の生成を強制しない。高負荷・長時間連続試験は本書の通常実行に含めない。

判定は`PASS`、`FAIL・調査中`、`FAIL・修正中`、`再試験待ち`、`一部確認`、`条件不足`、`未実施`、`対象外`を使います。`PASS`はその枝番の全期待条件を実測できた場合のみです。未提供機能・未採用構成は、実施時に根拠を記録して`対象外`にします。障害や社内プロキシに遮られた場合は、観測できた範囲と未確認部分を分け、成功扱いにしません。

### 2.4 証跡と実行順

- 証跡にはID、時刻、HTTP状態、公開エラーコード、APIM request ID、必要なら非秘密のSQL行参照・イメージdigestを記録する。認証URLのfragment、`pollSecret`、接続セッション、APIキー、OAuth code/token、SAS、Cookieを貼り付けない。
- 要求・応答本文、SQL出力、音声・画像が必要な場合は限定アクセスの試験保管場所に置き、本書には確認範囲・判定・残件の要約だけを記録する。実環境の原本へのリンクは公開せず、開発ツールやAPIM traceもそのまま共有しない。
- 画面エビデンスには、IaCで明示した設定を照合するnative設定画面・読取画面、リソースJSON表示、Azure Resource Graphの比較結果を含める。実際に見えた値・未表示項目・別途の読取API結果を区別し、撮影のために設定を変更しない。
- 推奨順: 既存環境の経路・匿名health → ログイン・権限・SQL → APIキーと共通認可 → Model/Tool正常系 → 本人接続・失効・異常系 → 同期・障害・運用 → 試験データの後片付け。
- 本書の全対象をクリアし、資材改修と修正後の再試験が完了したら、資材のGit revisionとparams・設定hashを固定する。その資材での再構築と構築テストは [別仕様書](construction-tests.md)・別試行IDで実施し、本書の既存環境の判定を流用しない。

### 3.2 認証・本人接続・購読管理・SQL

仕様作成時の基準は `main` の `c6ba7ca`。実施済みの範囲と残件は各行の結果を参照する。過去の別試行の合格結果を今回の判定へ転記しない。`G`はGatewayの公開origin、`P`はPortalの公開originとする。キー・Cookie・認証URL・pollSecret・セッション値は保護された実施者用保存先に置き、証跡にはマスク済み値、要求ID、時刻、対象IDだけを残す。

前提：同一の許可Entraテナント内に利用者A/B、Aが所属する適格グループG1、Bが所属する適格グループG2、基盤管理グループの管理者Mを用意する。共通前提の表記との対応は **A=U-A、B=U-B、G1=G-A、G2=G-B** とする。G1/G2は設定した`groupNamePattern`に一致する`securityEnabled=true`のグループ。別テナントXと、正規表現不一致または非セキュリティの対照グループも用意する。APIキーの試験には専用購読を使う。署名異常・応答消失等を実環境で安全に作れないケースは、現行実装の依存注入境界を使う隔離テストハーネスで行い、公開APIへ診断用の認証迂回口を追加しない。

期限試験は標準値の確認と境界試験を分ける。境界試験を短時間で行う場合は、専用の隔離環境に `idleTimeoutSeconds=600`、`absoluteLifetimeSeconds=1800`、`rotationIntervalSeconds=300`、`rotationGraceSeconds=60`、`rotationHandoffSeconds=120`、`rotationCandidateTtlSeconds=120` を設定し、新規認証した専用セッションを使う。既存の業務セッションや本番DBの時刻・期限を直接変更しない。変更・削除・失効・障害注入の行は専用環境限定で、対象IDと復旧方法を事前に記録する。

根拠：`apps/portal/lib/auth-{options,identity,schema,session,routes}.ts`、`apps/gateway/credential-broker/credential_broker/{settings,service,store}.py`、`apps/gateway/apim/policies/credential-{connection,session-use}.xml`、`docs/setup/credential-manager-login.md`、`apps/portal/lib/connection-session/`、`apps/portal/lib/api-keys/`、`apps/portal/lib/{api-key-administration,company-administration,subscription-sync}/`、各アプリの`sql/`をHEADから確認した。HTTPの失敗は対象層の契約で判定し、Gatewayの状態コードをPortal BFFの状態コードと混同しない。Gatewayの接続セッションはbearer資格情報であり、提示者のPortalログイン本人をGateway単体で再確認するものではない。

### 3.5 Model Gateway・リアルタイム音声

本節は `main` の `c6ba7ca` にある実装から作成した試験仕様です。この仕様の作成時には試験を実行していません。過去の動作確認結果は転記せず、全行を未実施から開始します。

#### 実施単位・判定方法

- **全件展開**：成功系で「全件」と記した行は、対象環境へ配備する API 定義の `authorization.operationConstraints`、`profiles`、`allowedModels` と解決済み `public-bindings.json` から、`API ID × operation ID × profile ID × model ID × transport` の一覧を作り、該当する全組合せで実施します。各実施を `TXT-01/<model>/<profile>` のような枝番で記録し、未配備・未実施のモデルを他モデルの成功で代用しません。現在のモデル名や件数を将来の固定上限にはしません。
- **Portal と直接 API の区別**：Portal は `getTextGenerationModels` などが返す候補だけを対象にします。Chat の `vision`、Responses の `pdf`、OpenAI/BFL の画像編集は現行 Portal の実行フォームに含まれないため、直接 Gateway API で確認します。Portal で未提供の機能を不具合や実施済みとして数えません。
- **上限の参照先**：以下の `L` は当該 operation/profile の `maxRequestBytes`・`arrayLimits`・`integerLimits`・`stringChoices`、`O` は `model-capabilities.json` の当該モデル能力、`P` は Portal の `*-request.ts`・`*-integration.ts` にある追加制限・既定値を指します。数値は試験準備時に読み取り、証跡へ記録します。境界は `L/P/O の許可上限ちょうど` と `その最小単位超過` を分け、UTF-8 のバイト数と文字数を混同しません。モデルの最大出力と、Portal の応答量・待ち時間・音声接続時間の保護上限も別です。
- **共通前提**：当該 API が許可された有効な検証用購読を選べる Portal 利用者、必要なモデル配備、音声試験ではヘッドセットとマイクを準備します。実行 URL は環境の公開 Gateway/Portal origin を使い、実キーを例へ直書きしません。本文は合成データを使います。正常系の生成内容は完全一致ではなく、返却形式・実モデル・意味的成立・手動判定で確認します。
- **異常系の方法**：実サービスで再現できない不正上流応答、途中切断、タイムアウト、リダイレクトは、外部公開しない検証環境の制御可能な上流で再現します。製品設定や本番サービスを壊して再現しません。これは自動テストの実施済みを意味しません。
- **証跡**：各枝番で日時、環境、commit、API/profile/model/transport、選択した購読の非秘密 ID、入力 fixture ID、HTTP 状態・終了理由・request ID、マスキング済みリクエスト/応答またはイベント要約を保存します。API キー、Cookie、通話 ticket、暗号化停止 handle、SDP、音声そのものを共有証跡へ含めません。音声の可聴性・字幕精度・停止は実機で人が判定し、接続成功だけで合格にしません。
