# 公開情報の混入検査

[AGENTS.md](../AGENTS.md)の禁止事項を、ローカルのGitフックとGitHub Actionsで補助します。実際の企業・環境情報は、ignore対象や作業記録であっても持ち込みません。

## clone直後の設定

Python 3.11以上とGitが必要です。外部パッケージは不要です。

```sh
python3 -I -B scripts/install_git_hooks.py
git config --local --get core.hooksPath
# .githooks
```

フックはcloneだけでは自動的に有効になりません。各cloneで設定します。既存の独自フック・hooksPathがある場合は上書きせず停止するので、管理者と統合してください。

| タイミング | 対象 |
| --- | --- |
| pre-commit | ステージされた全ファイルの実際のバイト列、著者情報、参照名、下記範囲の作業ツリー |
| commit-msg | コミットメッセージ、著者・コミッター、参照名 |
| pre-push | 到達可能な全履歴、削除済みファイル、著者・メッセージ・タグ、push対象SHAと送信先参照名 |

作業ツリー検査は未追跡・ignore対象も含み、`.state`、`.azure`、`.env`、`secrets`、作業記録・出力は除外しません。Git管理領域の`.git`と、依存・ビルド用の`.venv`、`apps/portal/node_modules`、`apps/portal/.next`の3か所だけを通常の作業ツリー検査から除外します。シンボリックリンクは除外前に拒否します。この除外をステージ・履歴の検査へ適用することはありません。`git add -f`しても検査対象です。

除外先も企業情報の保存場所にはできません。依存物は可能ならチェックアウト外へ配置します。リリース前には`--worktree-strict`で依存生成先も含めて確認でき、未知のバイナリー等は要確認として停止します。

手動で同じ検査を実行できます。

```sh
python3 -I -B scripts/check_public_data.py --staged --worktree
python3 -I -B scripts/check_public_data.py --all-history
python3 -I -B scripts/check_public_data.py --worktree-strict
python3 -I -B -m unittest discover -s tests -p test_public_data_guard.py -v
```

## 検出範囲と停止時の扱い

- 未承認のGUID、Azureの識別子、環境ID設定、テナント固有URL。
- 未承認のURLホスト・クラウドホスト・メール、IP、端末利用者の絶対パス。
- 代表的なAPIキー・トークン・秘密鍵・認証情報の設定・認証付きURL。
- UTF-16、URLエンコード、Unicodeエスケープ、代表的なBase64の内側も上限付きで検査。
- 未承認または変更されたバイナリー、埋め込み画像、過大なファイル、シンボリックリンク等は要確認として拒否。
- shallow履歴、読取失敗、不正ポリシー、検査起動失敗は成功にしない。

検出値、本文、ファイル名、そのハッシュはログへ出しません。規則名・実行内の連番・行番号だけを表示します。ローカルフックとCIはさらに検査出力を捕捉し、固定した成否だけを通知します。調査時にも実値をIssueやCIログへ貼らず、安全な作業領域で確認してください。

任意の企業名や顧客固有語もローカルで検査する場合は、チェックアウト外の保護したUTF-8ファイルに1行1語で保存し、`EGAKUMI_PRIVATE_TERMS_FILE`で指定できます。このファイルや内容を本リポジトリ・公開の設定・コマンドラインへコピーしません。設定時に読めない、空である、チェックアウト内を指す場合は検査を拒否します。この個別辞書はGitHubへ送信せず、標準CIには設定していません。

## 許可リストの管理

正本は[scripts/public-data-policy.json](../scripts/public-data-policy.json)です。公開仕様のAzure組み込みRBACロール、共通ホスト、公開用著者情報と、既存の合成例・テスト値を区別しています。文書用ドメイン・IP・明示的プレースホルダー以外の例外は、規則・値・完全一致のファイルパス・理由を指定します。テストディレクトリ全体、GUID全般、プライベートIP全体、Azureのサービスドメイン全体の除外は行いません。

画像・音声等は、人が表示内容・メタデータ・埋め込みを確認した配布素材のパスとSHA-256が一致する場合だけ許可します。ハッシュは承認済み公開素材の整合性確認用です。実値や機密ファイルをハッシュにして許可リストへ入れてはいけません。ファイル変更後は再確認が必要です。

検出された値をそのまま許可リストへ足して通過させません。企業固有情報なら除去し、独立した架空例を作ります。新たな公開定数・配布素材の承認は、根拠と権利を確認し、先にポリシーの変更をレビュー・反映してから、次のPRで利用します。PR中の許可リストは、そのPR自身の検査を緩めません。

## GitHub側の検査

[Public data guard](../.github/workflows/public-data-guard.yml)は、保護された正本側の検査コード・ポリシーを使います。PRでは`pull_request_target`からGitオブジェクトだけを別領域へ取得し、候補の作業ファイル・Python・テスト・フックを実行しません。検査結果はPRのhead SHAへ固定名のstatusを送信し、必須チェックでmainへの取り込みを止めます。push時・手動実行時も検査します。検査jobはcontents読み取りだけ、status通知jobは必要なstatus書き込みだけを使います。

初回導入時だけ、管理者がレビュー済み導入コミットをリポジトリ変数`PUBLIC_DATA_GUARD_BOOTSTRAP_REVISION`へ設定します。信頼できる検査資材を取得できなければ失敗します。通常の更新は保護されたmainの検査資材を使います。

スキャンは既知の構文を検査する補助です。任意の自然言語の企業情報、画像・音声の意味、すべての符号化・分割・派生値を自動判定できません。GitHub Actionsはアップロード後に動くため、GitHubへ最初の送信が行われる前の防止はローカルの確認・フック・作業領域の分離で行います。フックの未設定や`--no-verify`、管理者による保護設定の変更までは防げません。スキャン通過だけで公開可能と判断せず、差分・素材・メタデータの人による確認も続けます。
